# fbs-funnel-report

Аналитический отчёт **FBS-воронки** (заказ → выкуп / отмена / возврат) из PostgreSQL
в XLSX. Считает по сырым таблицам загрузчика
[`download-wb-fbs-orders-v2`](../../data-downloaders/download-wb-fbs-orders-v2/),
только `SELECT` — ничего не пишет в БД.

Главный вопрос: **реальная выручка периода, которая зависит от процента выкупа**
(выручка = выкуплено ₽; упущено = отмены + возвраты), и её динамика по дням и когортам.

## Запуск

```bash
# весь диапазон данных, прод:
go run ./cmd/data-analyzers/fbs-funnel-report/

# последние 30 суток, тестовая база:
go run ./cmd/data-analyzers/fbs-funnel-report/ --days 30 --db wb_data_test

# включая FBW (по умолчанию — только склад продавца is_mp):
go run ./cmd/data-analyzers/fbs-funnel-report/ --all-models

# плюс самодостаточный HTML-дашборд (offline, фильтры в браузере):
go run ./cmd/data-analyzers/fbs-funnel-report/ --html auto
```

Выход: `reports/fbs-funnel-<дата>.xlsx` (переопределяется `--xlsx` / `config.yaml`).
Секреты — из `.env` (`PG_PWD`); загрузка: `set -a; source .env; set +a`.

## HTML-дашборд (`--html auto` | путь)

Один самодостаточный файл `reports/fbs-dashboard-<дата>.html` (~3–10 МБ):
echarts 5 завендорен в `assets/`, данные — JSON-куб внутри; открывается двойным
кликом без сети. Разрезы и фильтры считает браузер (один проход по фактам,
~70–200k строк): KPI (выручка/упущено/% выкупа/чек/цикл), деньги по
дням-неделям с % выкупа и MA-7, воронка периода, когорты с пометкой незрелых,
причины упущенного в ₽, география (топ-300 городов + «Прочие»), категории 1С
(`cards.vendor_code → onec_goods.article`, уровень 1 → уровень 2; без 1С-словаря
— фолбэк на предмет WB с маркером «WB ·»), топ номенклатур со спарклайнами.

Период задаёт **только шапка** (пресеты 7/14/30/всё) — у графиков нет своего
зума. Кросс-фильтры: клик по городу/категории/строке таблицы пересчитывает весь
дашборд; активные фильтры — чипами в шапке. База ≠ `wb_data_prod` помечается
бейджем «ТЕСТ». Термины — кнопка «Глоссарий» (те же определения, что в XLSX:
один источник `glossarySections()`).

Зерно куба: (когортная дата, дата события, nm, город-бакет, статус, причина
отмены) → количество + копейки; окно — по дате создания (когорты в файле полные).

## Листы

| Лист | Что показывает |
|------|----------------|
| Сводка | итоговая воронка + деньги (выручка/упущено/средний чек) + покрытие источников |
| Глоссарий | определения: когорта vs динамика, статусы, метрики, деньги, источники |
| Динамика | события по дням: день = дата перехода (`updated_at`), выкуп/отмена/возвраты + ₽ |
| Когорты | по дню создания (лента) с пометкой зрелости (возраст ≥ p90 цикла) |
| Когорты v3 | те же когорты из v3-снимка статусов (`sold`/отменено/в работе) |
| Причины отмен | день × `cancel_type`: receipt (при получении) / app (до получения) / expire / other |
| Скорость ЖЦ | медиана/p90 цикла заказ→выкуп, в целом и по когортам |
| География | города/районы назначения: заказы, % выкупа, выручка |
| Топ номенклатур | воронка по nm_id (сортировка по упущенной выручке), артикул/предмет из `cards` |
| Кросс-проверка | покрытие ленты относительно v3 по `rid=srid` по когортам |
| Методика | источники, семантика полей, оговорки |

## Методика (кратко)

- **Динамика по дням** строится на семантике ленты `order-feed`:
  `updated_at` = дата **текущего** статуса
  (`docs/wb_api_swagger/11-analytics.yaml:6414`), поэтому для выкупов
  `updated_at::date` — это день выкупа. Статусы: `created/buyout/cancel/return/returnDefective`.
- **Когорта зреет ~p90 цикла** (лист «Скорость ЖЦ»): у более молодых когорт доля
  выкупа смещена вверх — попадают только быстрые переходы; в отчёте такие помечены
  «Зрелая когорта = нет».
- **v3-снимок** (`fbs_orders` × `fbs_orders_status`) — канон полноты: статусы
  `sold` = выкуп, `canceled*`/`declined_by_client` = отмена
  (`docs/wb_api_swagger/03-orders-fbs.yaml:664`). Дат переходов v3 не несёт —
  только снимок на момент прогона загрузчика; история шагов копится отдельно в
  `fbs_orders_status_log`.
- **Край окна ленты**: заказы, чей текущий статус старше `feed_days` загрузчика
  (по умолчанию 7), в ленту не попадают — когорты до края окна неполны
  (см. «Кросс-проверка»). Расхождение v3↔лента ~1–5% — дрейф offset-пагинации
  ленты за время живого прогона.
- **Деньги**: `seller_price` — цена продавца **без** комиссий/логистики WB.
  Финансовая выручка к выплате — отдельный домен (finance API), здесь не учитывается.
- Дни считаются по `Europe/Moscow` (`AT TIME ZONE`), независимо от таймзоны сессии PG.

## Конфиг

`config.yaml` рядом с утилитой; приоритет CLI > YAML > дефолты. Ключи: `days`,
`all_models`, `storage` (`pg_database`, `pg_password_env`, …), `xlsx`, `html`
(`""` = не собирать, `auto` = стандартное имя).
